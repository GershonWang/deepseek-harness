# Agent Note：双客户端包的切换器独立成模块并改用托盘

Status: implemented

[English](2026-10-10-dual-client-tray-switcher.md) | 中文

## 问题

双客户端玲珑包要让用户选择两个客户端里跑哪一个，并保证至多一个在跑。最初的实现把这个控制面放在 launcher 二进制里，即 `--mode=bubble`：一个置顶、透明的 72×72 Wails 窗口，负责拉起客户端并终止它们的进程组。一天之内有五个修复提交全部在处理窗口合成行为——透明窗口画成黑色、投影变成黑边、单击没反应、切换卡满停止宽限期、拖拽后的位置需要记住。

持久化的屏幕坐标是一条不可恢复的失效路径。换显示器之后球可能落在可见区域之外，而球是够到那个仍在运行的客户端的唯一方式。切换器还住在 launcher 的进程、embed 树与语言字典里，因此它没有任何一部分能被独立拥有或独立测试。

## 决策

切换器就是 `apps/linyaps/desktop-dual`：自己的 Go 模块与自己的二进制 `dsh-desktop-switcher`，以 `CGO_ENABLED=0` 构建，只依赖 `github.com/godbus/dbus/v5`。它以 StatusNotifierItem 加 dbusmenu 菜单注册，并把客户端作为子进程拉起或停掉。

`internal/switchboard` 原样迁入，因为它只 import 标准库。它把薄壳客户端解析为 `<PREFIX>/bin` 下的兄弟二进制 `dsh-desktop-launcher`，不再重新执行自己，因此 launcher 的 `--mode=bubble` 模式、`bubble.*` 前端资源与字典里的八个 `bubble.*` 键都已删除。

托盘项通过三个面报告形态：图标上的角标、本地化的提示文字，以及菜单首项——首项永远写着另一个形态的名字。托盘图标无法承载文字，因此悬浮球当年显示的形态标记字符串由这三者取代。

左键是「显示客户端」而不是切换：切换是破坏性的，必须留在显式菜单项后面；而误关的客户端必须一次点击就能回来。两个客户端的关闭语义不同，这一下点击同时照顾两边——薄壳版关窗即退出，点击会重新启动它；官方版关窗只是隐藏窗口，点击会再启动一次它的二进制，由 Electron 的单实例锁把这次启动变成聚焦请求。`ItemIsMenu` 置为 false，宿主才会把左键作为 `Activate` 送达而不是直接展开菜单。右键菜单里有切换项、「设置」子菜单（两项是 dbusmenu 单选项，当前默认那项带勾选标记）、「关于」与「退出切换器」（会连带停掉客户端）。动作失败会弹一条桌面通知并写明是哪一步没成，同时把该项状态置为 `NeedsAttention`。

「默认启动」用单选项而不是把当前项置灰：置灰看起来像「这一项不可用」，而它表达的只是一个状态；单选标记既说清状态又保留可点性。默认形态变化通过 `ItemsPropertiesUpdated` 报告，宿主原地更新受影响的项；`LayoutUpdated` 只留给菜单形状变化。刻意避开整树更新：在用户正交互时重建弹窗，会把 DDE 的托盘弹窗打进 `SurfacePopup.qml` 读 null 的 `x`/`y` 的坏状态，此后**所有应用**的托盘菜单都弹不出来，只能重启 `dde-shell@DDE.service` 恢复。DDE 用 `libdbusmenu-qt5` 渲染 dbusmenu，它既认 `toggle-state`，也认 `ItemsPropertiesUpdated`。

「关于」由 `dsh-desktop-about` 画出——一个由 `prepare-offline.sh` 编译、与切换器同目录安装的 GTK3 小程序。切换器是 `CGO_ENABLED=0` 的二进制、不带窗口工具链，容器里也没有 zenity、kdialog 或 Qt；GTK3 本来就在（薄壳客户端依赖它），因此一个只负责画窗口的助手比引入一套对话框运行时更便宜。所有面向用户的文案仍留在切换器的语言字典里、以命令行参数传入，助手不留副本。助手在每次尺寸分配后自己把窗口摆到显示器工作区正中：GTK 的位置提示只是给窗口管理器的建议（DDE 的窗口管理器并不采纳），而在尺寸分配回调里读到的尺寸还是上一次的值。

每个会话只允许一个切换器，由 well-known 总线名保证。会话里没有 `org.kde.StatusNotifierWatcher` 时，切换器按默认形态启动客户端、记录原因，并每五秒核对一次，因此桌面外壳回来时入口随之恢复。核对还会把宿主的连接唯一名与注册时记下的那个比对，因此外壳崩溃后由新进程接管时，托盘项会被重新注册，而不是留下一个没有可见入口的常驻切换器。

本包只导出切换器一个桌面入口：`install-shell-runtime.sh` 还会安装薄壳版包自己的入口，那条入口会在切换器之外拉起客户端，破坏互斥切换。

## 考虑过的替代方案

**保留悬浮球，把切换器抽成一个仍然链接 Wails 的模块。** 否决：切换器会需要 launcher 的容器适配（WebKit helper 路径、渲染配置、fontconfig），那就得抽出共享模块并跨模块使用 `go.work` 或路径替换，而窗口本身的失效模式一个都没消失。

**改用 DDE 自己的托盘插件接口。** 否决：`PluginsItemInterfaceV2` 是 dde-tray-loader 从宿主插件目录加载的进程内 C++/QML 插件。玲珑包只读且无提权，装不进也注册不了。

**把切换器源码挪进 `desktop-dual` 但保持一个二进制。** 否决：Go 模块不能包含自身目录树之外的包，`go:embed` 也够不到包目录之外，因此只挪文件改变不了归属。

**继续在前端轮询而不是在 Go 侧。** 否决：已经没有前端了。状态仍按每秒一次轮询，与悬浮球当年一致；状态量极小，而且客户端可能在切换器之外退出。

**「关于」改用桌面通知。** 否决：通知是切换器本来就有的唯一渠道，但通知不是对话框——它落在通知中心而不是用户正看着的屏幕上，也带不了产品图标与「关于」本来就要展示的版本信息。

**用容器里现成的 `xmessage`。** 否决：它确实已经装好，但走的是 X11 核心字体路径、画出来是 Motif 时代的外观，中文会缺字形——而中文恰好是「关于」必须显示正确的那部分。

## 后果

切换依然是破坏性的：停掉当前客户端的进程组、拉起另一个，正在进行的会话会中断。这与悬浮球时期一致，仍是产品决策。

托盘项无法用文字显示形态名；形态身份由角标颜色加提示文字与菜单首项表达。角标配色与两种几何回退图形都有单测覆盖，随包图标缺失时图标回退为画出来的圆。

`desktop-dual` 与 `desktop-launcher` 不共享任何 Go 包，因此 launcher 的 Wails 与 WebKit 依赖、容器适配都留在它自己模块里。

已在玲珑容器内对宿主会话总线实测：托盘项注册成功并出现在宿主的登记列表里、提示文字带本地化形态名、`GetLayout` 返回预期条目、菜单 `Event` 写入默认形态、退出后注销、第二实例按单实例名退出。左右键的分工在改代码之前就对真实宿主验证过：`ItemIsMenu` 为 false 的探针项在左键收到 `Activate`、在右键被取走布局，且带子菜单的菜单能正常渲染。勾选渲染用同样的办法量过——一个探针放单选对、另一个同时放 radio 与 checkmark 的勾上/未勾：`toggle-state` 为 1 画勾、为 0 什么都不画，因此单选对只会出现一个勾。通知种类同样在改代码前验证过：探针翻转这对状态后**只**发 `ItemsPropertiesUpdated`，勾会移到被点的那项、另一项的勾被清掉。「关于」的居中用 `xwininfo` 量外框：中心与屏幕中心相差不超过 1 像素，而修复前偏 (−175, −106)。重新注册由两条证据覆盖：包内测试在私有总线上换掉宿主的连接，以及用桩宿主运行已构建的二进制——修复前的二进制在新宿主上一无所获，修复后下一次核对即完成注册。`Present` 的三条分支、菜单树的子菜单协议面、以及切换器传给「关于」助手的参数都有单测覆盖。互斥性用模拟安装布局下的假客户端实测：首个客户端启动，一次切换终止它并拉起另一个，退出时终止剩余客户端。
