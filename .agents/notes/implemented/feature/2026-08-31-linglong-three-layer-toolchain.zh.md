# Agent Note：在玲珑客户端中把工具链外置为三层可插拔结构

状态：已实现

[English](2026-08-31-linglong-three-layer-toolchain.md) | 中文

## 问题

玲珑桌面客户端把固定的编译器/工具链集合打包进应用内，包体逼近约 431 MB，且工具集在构建期即被冻结。用户想新增、移除工具或固定某个版本，都必须重新打包整个 `.uab`。产品要求恰好相反：工具链放在应用之外，用户把任意工具热插拔进运行中的客户端。工具的可用性与完备性优先于包体大小，因此重构不得让任何工具比在宿主上更难用。

## 决定

客户端按优先级从低到高在三个可插拔层中解析工具：

- **L1 内置**——包内只读的约 150 MB 最小集合，在用户尚未安装任何工具时兜底。
- **L2 一键安装**——工具安装到 `~/.dsh-tools`（用户 HOME 内共享），支持多版本、sha256 校验、原子解包、下载缓存，以及带 24 小时缓存和内置兜底的远程目录索引。
- **L3 宿主导入**——用户把宿主工具链目录只读绑定进沙箱（config.d），重启应用后生效。

目录是单一 JSON 源 `internal/toolchain/tools/index.json`，用 `go:embed` 内嵌进启动器，运行时可用同构的远程索引覆盖（URL 可配，默认指向分支上的仓库副本）。项目级 `.dsh-toolchain.yml` 为各工具固定版本，并在用户打开该项目时自动切换激活版本。宿主导入向导扫描常见工具链根目录，对每个候选探测 `--version`，再写入挂载配置。

## 备选方案

**继续把工具链打包进应用**——否决。`.uab` 持续偏大，且每次工具更新都要重新发布应用。

**用玲珑 `modules`/`ext_defs` 作为工具链仓库**——否决。玲珑应用层模块市场才是工具链的正确载体，而非 base/runtime 的模块清单；上述三层正是接入该市场。

**安装到无版本的单目录**——否决。项目固定版本与回滚需要多版本安装加激活软链。

**不做下载缓存、每次都现取**——否决。按 sha256 作为键的缓存让重复安装与离线安装变得确定，并能抵御 GitHub 发布页的偶发抖动。

## 后果

包体收缩到只含 L1 的体积；每增加一个工具，代价从包体字节变为安装期下载。完整性现在依赖 sha256 校验加原子解包，宿主导入需重启应用后挂载才可见。远程目录故障时依次降级到 24 小时缓存再降级到内置目录，市场在离线时仍能渲染。代价是更大的 Go 面（catalog、install、remote、project、host 发现）以及带进度、版本切换、卸载的市场 UI——这些都是三层结构保持外部可插拔所必需的。
