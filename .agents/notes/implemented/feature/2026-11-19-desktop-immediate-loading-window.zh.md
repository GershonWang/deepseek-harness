# Agent Note: 桌面启动时立即放出加载窗口

Status: implemented

[English](2026-11-19-desktop-immediate-loading-window.md) | 中文

## Problem

桌面冷启动把主窗口创建为隐藏状态，直到 Host 回复 ready 才显示。于是 profile 准备、登录 shell 探测、Host 模块加载、插件激活与欢迎状态 RPC 全部执行期间，屏幕上只有托盘：在报告机器上，215 条 loader 条目的 profile 光 Host 就要 3.1–4.6 秒，而渲染器文档加载还被串行排在 Host 启动之前。共享 Web 加载页本就会为这段时间绘制进度，只是一直落在屏幕外。

## Decision

[`reconcileBackend`](../../../../apps/desktop/src/main.ts) 让加载文档与 Host 并行启动，不再先等文档加载完才拉起 Host，并在文档加载完成后立即放出主窗口。窗口仍以隐藏方式创建，因为登录态决定最终允许出现什么；当 Host 要求凭证时，`showWelcome` 会先收起已放出的文档再打开欢迎窗口，工作区不会因此提前可见。Host 启动失败时文档保持可见，恢复操作就在这个窗口里呈现，不再另起一个窗口。

托盘入口与 `dsh://open` 现在会聚焦已放出的加载窗口，而不是直接返回。仍处于隐藏状态的启动窗口继续等待启动流程做出选择，从而避免迟到的激活请求在凭证检查之前露出工作区。放出只发生在启动收敛阶段；之后的 Host 重启与更新恢复本来就有可见窗口。

## Alternatives considered

**独立的原生 splash 窗口。** 专用小窗可以不加载 Web 文档就展示品牌与进度，但会多出第二套启动界面、它自己的文档，以及与托盘、单实例、关闭行为对齐的交接逻辑。Web 加载页本来就会绘制真实进度，并且随后就是工作区文档。

**保持窗口隐藏直到 Host 就绪。** 这样可以避免向未登录用户展示他们并不需要的加载文档，但整段启动没有任何反馈，托盘激活也形同虚设，读起来像卡死。

**等拿到 Host 主题偏好后再放出。** 调色板最多只切换一次而不是在放出时切换，代价是把这段本该由加载页覆盖的启动时间重新藏起来。可接受的闪烁小于这段等待。

## Consequences

冷启动约一秒内就能看到加载页；未登录的启动会一直看到 Host 就绪，再由欢迎窗口接管。加载页在 Host 主题偏好到达前使用系统调色板，因此显式的浅色或深色选择可能带来一次重绘。关闭加载窗口仍然只是隐藏窗口，启动完成后会出现流程选中的界面。
