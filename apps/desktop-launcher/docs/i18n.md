# 桌面启动器国际化（i18n）方案

> **目的**：把启动器外壳的用户可见文案从「写死中文」改为「跟随 harness GUI 的实际语言」，并给出可执行的分期实施与验证方案。
> **范围**：只覆盖 `apps/desktop-launcher/`（Go + Wails 壳、`frontend/` 静态资源、`linglong/` 打包链）。**本文档不含任何代码改动**，第七节的各期均为待执行计划。
> **状态**：方案与范围（**P0–P2**：壳前端 + Go 侧用户可见文案）已与维护者确认（2026-09-21）。**P0 与 P1 第①批已实施**（标题栏、引导页、加载页、预检页、失败页、状态栏），其余待做。对应审计条目 [AUDIT.md](./AUDIT.md) 第 24 条（低危·未修）。

## 二、现状

### 2.1 技术形态

启动器是 Go 1.25 + Wails v2.15 应用，前端为**零构建**的 vanilla JS/HTML/CSS，经 `//go:embed all:frontend`（`main.go:22`）内嵌进二进制。`frontend/index.html:359-361` 用三个普通 `<script>` 标签加载 `vendor/xterm.js`、`vendor/addon-fit.js`、`app.js`；`app.js` 是全局作用域脚本，**无 import/require、无打包器、无模块系统**。任何国际化机制都必须在这个约束内成立。

harness GUI 以 iframe 形式内嵌（`frontend/index.html:56`），其语言由 `@deepseek-ai/dsh-client-locale` 独立管理，与壳互不相通。

### 2.2 文案分布（实测）

| 位置 | 数量 | 说明 |
|---|---|---|
| `frontend/index.html` | 70 个中文文本节点 + 29 条属性文案 | 属性为 `title`/`placeholder`/`aria-label`/`alt`；覆盖标题栏、引导页、加载页、预检页、失败页、状态栏与 5 个弹框 |
| `frontend/app.js` | **186 个含中文的字符串字面量** | TypeScript AST 扫描所得，已排除注释 |
| Go 非测试源码 | **80 个中文字面量** | 剥注释后的字面量扫描所得；粗分类为「返回前端的 error」15 条、「消息拼接」7 条、「结构体消息字段」3 条、其余 55 条（Wails 对话框标题与按钮、工具链状态文案、关于弹框标签、日志与覆盖层头注释等） |

### 2.3 用户可见后果

harness GUI 的语言服务在浏览器未给出已注册语言时**回退英文**（`packages/client/locale/src/client/index.ts:107` 的 `FALLBACK_LOCALE = 'en'`），并按 `navigator.languages` 匹配（同文件 `:518`）。因此**英文系统用户当前看到的是「英文的 harness GUI + 中文的启动器外壳」**——这是本问题的真实用户可见表现，也是它的定级依据。

## 三、目标与非目标

**目标**

1. 壳的全部用户可见文案（前端与 Go 两侧）支持 `zh`/`en`，默认跟随 harness GUI 的实际生效语言。
2. 新增文案有自动化兜底：硬编码产品文案会被闸门拒绝，字典缺键会失败。
3. 中文用户的现有体验零回归；英文系统用户不再看到中文壳。

**非目标（本期明确不做）**

| 不做项 | 原因 |
|---|---|
| 工具索引 `index.json` 的 `name`/`description`/`category_labels` | 远程数据，改动涉及索引 schema 兼容，单列 P4（未排期） |
| 壳自己的语言切换 UI | 真源就是 GUI 的 Settings → General → 语言，壳再设一处会产生两个真源 |
| harness `dsh doctor --json` 的 `message` | 文案由 harness 侧产生且**只有英文**（`packages/support/doctor/src/checks/*.ts` 无 locale 支持）。诊断面板的中文 chrome 包着英文检查项是既有事实，本方案修不了，列为已知边界 |
| `README.md`/`README.zh.md` 文档翻译 | 已有 `verify-translation-pairing` 流水线；若实施中改动 README，必须同步另一侧并重录 `README.i18n.yaml` |
| `linglong/com.deepseek.dsh-desktop.desktop` | 已含 `Name[zh_CN]`/`Comment[zh_CN]`，按需补语种即可，不属本方案主体 |

## 五、真源与数据流

### 5.1 真源：GUI 维护的 `<html lang>`

harness GUI 的语言服务**已经在维护 `<html lang>`**：

```ts
// packages/client/locale/src/client/index.ts:146-149  每次 locale 快照变化时同步
document.documentElement.lang = snapshot.active === 'zh' ? 'zh-CN' : snapshot.active
// 同文件 :553  在 locale 插件激活时安装
syncDocumentLanguage(snapshot)
```

`packages/bundle/web-app/cordis.patch.yml:204-205` 把 `@deepseek-ai/dsh-client-locale` 编入 `web-app` profile —— 这正是启动器通过 `dsh web` 启动的 profile。因此**只要 GUI 起来，`<html lang>` 就是「用户实际生效语言」的权威且实时的信号**（含用户偏好、浏览器兜底、语言包三方扩展的结果）。

壳与 GUI 之间**已有现成的 postMessage 桥**：GUI 侧是 `linglong/dsh-link-bridge.js`（打包期由 `linglong/inject-link-bridge.sh` 注入 dist，与页面同源、先于 module 入口执行），壳侧是 `frontend/app.js:110-168` 的 `message` 监听器，已用 `e.source === frame.contentWindow` 做来源校验，且对未知 `type` 天然忽略。

### 5.2 三条候选路径对比

| | ① 壳读 `$DSH_HOME/settings.yaml` | ② GUI `<html lang>` 上报（**选定**） | ③ 壳自己存语言设置 |
|---|---|---|---|
| 新增依赖 | 需引入 YAML 库（Go 侧现无任何 YAML 依赖） | 零 | 零 |
| `DSH_HOME` 重定向（安全模式 / 全新环境，`internal/app/preflight.go:234`） | 壳需自行跟踪生效 home | 天然跟随（GUI 在哪个 home 就跑哪个） | 与 GUI 无关，会不一致 |
| 用户在 GUI 内切换语言 | 需轮询文件比对 | 立即同步 | 不同步 |
| 拿到的语义 | 用户偏好（可能缺省） | **GUI 实际生效的语言** | 壳自己的偏好 |
| 私有契约面 | harness 设置文档格式（`packages/settings/settings-file/src/index.ts:57`） | 一个 Web 标准属性，且该行为已在 locale 包 JSDoc 中声明 | 无 |
| 预检 / 加载 / 失败页（GUI 未起） | 可读文件 | 需兜底 | 可用 |

路径 ① 的三条硬障碍（YAML 依赖、`DSH_HOME` 重定向、私有文件格式契约）是放弃它的直接原因。

### 5.3 解析优先级

```
① GUI 上报（权威，实时）
      ▲  MutationObserver(attributeFilter: ['lang']) → { dshDesktop: true, type: 'locale', id }
      │
② navigator.languages → navigator.language（GUI 未起来时的兜底，与 GUI 自身的兜底同源同规则）
      │
③ 默认 en（与 packages/client/locale 的 FALLBACK_LOCALE 及 apps/desktop 的 resolveDesktopLocale 一致）
```

兜底使用 `navigator` 而非环境变量，是为了让壳的兜底与 GUI 的兜底**由构造保证一致**（同一 webview、同一来源）。`locale id` 归一化：`zh`、`zh-CN`、`zh-*` → `zh`；其余已注册语言 → 对应字典；未注册（如三方语言包 `ja`）→ `en`。

### 5.4 依赖的第三方契约

本节列出实施后**壳对 harness 的隐式依赖**，改动上游时须同步核对：

| 契约 | 位置 | 失效后果 |
|---|---|---|
| locale 插件维护 `<html lang>` | `packages/client/locale/src/client/index.ts:146-149`、`:553` | 桥收不到变更 → 壳退回兜底语言，功能降级不报错 |
| locale 插件在 `web-app` profile 中启用 | `packages/bundle/web-app/cordis.patch.yml:204-205` | 同上 |
| 桥的注入点 `</body>` 与 dist 结构 | `linglong/inject-link-bridge.sh` | 注入失败会中止构建（已有 fail-loud 保护） |
| postMessage 协议 `{ dshDesktop: true, type }` | `frontend/app.js:110-168`、`linglong/dsh-link-bridge.js` | 双向：旧壳忽略未知 `type`，旧桥不发消息 → 各自退回兜底，无破坏 |

### 5.5 Go 侧 locale 的来源（P2 需要）

壳的 Go 代码在**前端加载之前**就要产出用户可见文案（预检页错误、启动失败原因、Wails 原生对话框），不能等前端告知。采用「前端推送为准 + 环境 locale 兜底」：

```
① 前端 applyLocale(id) 时调用 App.SetLocale(id)      ← 权威，随 GUI 语言实时更新
② 环境 locale（LC_ALL → LC_MESSAGES → LANG，归一化 zh/en）  ← 启动初值
③ 默认 en
```

② 与前端兜底的 `navigator` 同源（都由系统 locale 决定），两处初值通常一致；不一致时以前端推送为准。Go **不持久化** locale——真源是 GUI 的设置，壳只持有内存中的当前值。

已知取舍：语言切换后，**已经渲染在页面上的 Go 文案**会在下一次状态快照重绘时更新；一次性提示（如安装失败 toast）不回溯。这与「状态每秒推送」的既有机制一致，不需要额外机制。

## 六、字典与命名规范

### 6.1 文件布局（零构建约束下）

```
frontend/
  locales/
    zh.js        # 键全集真源，中文文案（当前写死的文案搬到这里）
    en.js        # 与 zh 同键集，英文文案（见 6.5 的过渡状态）
  i18n.js        # t() / applyLocale() / data-i18n 回填；不含任何产品文案
  index.html     # 只留 data-i18n* 钩子，不留文案
  app.js         # 动态文案改走 t()
```

三个新文件都是普通脚本，挂在全局（如 `window.DSHI18N`），由 `index.html` 在 `app.js` **之前**加载，与现有脚本模型一致，不引入构建链。字典目录名取 `locales/`，可直接命中 `scripts/verify-client-ui-i18n.ts` 的 `localeOwner()` 规则（路径含 `/locales/` 即视为字典所有者），闸门无需新增例外。

### 6.2 键与占位符

- 键为点分命名空间（如 `titlebar.server`、`market.install.failed`），与仓库既有 `LOCALE_KEY` 形态一致。
- 占位符沿用 `apps/desktop/src/locale.ts:195` 的 `{name}` 约定，替换函数同语义（未知占位符原样保留，便于暴露漏配）。
- 计数类文案（如「已加载 {loaded}/{total} 个插件」）必须整句进字典，禁止在代码里拼接词序——英文语序与中文不同。

### 6.3 HTML 钩子

| 钩子 | 作用对象 |
|---|---|
| `data-i18n` | 元素文本 |
| `data-i18n-title` / `data-i18n-placeholder` / `data-i18n-aria-label` / `data-i18n-alt` | 同名属性 |

`applyLocale()` 遍历 `[data-i18n]` 等选择器回填；`index.html` **不留中文兜底文案**（单一真源，避免字典与 HTML 两份漂移）。代价是 `frontend/tools/preview.mjs` 会剥掉 `<script>` 后量几何——该工具必须同步注入字典，否则静态面板的几何断言会因文案消失而误报。**这一条不是收尾项**：第一批钩子落地起预览就必须内联字典并在页内应用 `zh-CN`，否则 `preview.mjs verify` 立刻误报（第①批已实施）。

### 6.3.1 两类无法整句进字典的文案

句子结构里夹着非文案成分时，按下列两种既定写法处理，都不把 HTML 放进字典：

| 情形 | 写法 | 例 |
|---|---|---|
| 句中夹内联 `<code>`（命令、地址） | 拆成 `<scope>.<what>.before` / `.after` 两个键，内联元素留在 HTML 里当兄弟节点 | `guidance.remote.hint.before` + `<code>dsh web --host &lt;LAN-IP&gt;</code>` + `.after` |
| 文案后跟一个数据值（主机端口、日志路径、退出码） | 数据留在 HTML 或代码里，只把标签/状态词进字典；带值的那句用 `{name}` 占位符 | `status.runningWithHost`、`failed.logHint`（冒号后是路径） |

为什么不用富文本（把 HTML 塞进字典值再 `innerHTML`）：仓库既有客户端文案没有这种机制，且字典一旦接受 HTML，注入面就从「代码」扩大到「翻译文件」。代价是英文语序必须与中文一致地容纳内联元素——这两种情形里内联元素都是命令或数据，位置天然稳定；真需要调整语序时再引入占位符元素机制，而不是先造一套用不上的机制。

### 6.4 缺键与回退

运行时缺键 → 回退 `zh` → 仍缺则显示键名本身（与仓库既有行为一致，便于暴露漏配）。`en.js` 缺键在闸门层**直接失败**（见 8.4），不允许静默上线。

### 6.5 `en.js` 的翻译状态

`en.js` 与 `zh.js` 同键集；已迁入区域（79 条）的英文由 AI 起草、**待维护者审校**。未迁入区域的文案仍在代码里，不在字典内，因此不存在「字典缺一块」的中间态。

键集与翻译状态由 `test-i18n.cjs` 的「字典完整性」用例守住，三条都是硬失败：

- `en` 与 `zh` 键集不一致（漏键或多键）；
- 同键的 `{name}` 占位符不一致；
- 值与中文逐字相同（等于漏翻），白名单只有 `status.exitCode`——它只包一个纯数字占位符，两种语言同形。

为什么是硬失败而不是「未翻译计数」提示：值相同意味着界面上真的会露出中文，靠人记「还差多少条」迟早漏掉；白名单只有一条，将来要加例外必须显式写进用例。该用例已用「注入漏翻 / 占位符不符 / 缺键三种缺陷必须失败」自证过。

### 6.6 Go 侧字典的组织（P2）

`internal/i18n` 是**叶子包**（不依赖任何内部包），只含三件事：locale 归一化、`zh`/`en` 两份字典、`T(locale, key, args…)` 纯函数。领域包**不依赖 `i18n`**，只报枚举事实，由 `app` 绑定层在边界渲染——这是决策 C 的落法（携带枚举的错误类型定义在领域包内，`i18n` 不认识它）：

| 现状 | 改后 |
|---|---|
| `internal/toolchain/install.go:136` 的 `InstallProgress(phase, percent, message)`，15 处调用各自拼中文 | 去掉 `message` 参数，只报 `phase`/`percent`。**前端本来就只渲染 `Phase`+`Percent`**（`app.js` 中没有任何 `ev.Message` 读取），该参数是死数据 |
| `install.go:152` 的 `classifyError(err) string` 返回中文 | 返回领域自有的 `ErrorKind` 枚举（`noSpace`/`permission`/`timeout`/…），`friendlyError` 返回携带 kind 的错误；`app` 层用 `errors.As` 取出后按当前 locale 渲染 |
| `app.go:1189` 的 `updateNotice`、`:1112` 的 `classifyRuntimeSource`、`:1459` 的 `joinOrNone` 直接拼中文 | 改为返回 key + 参数，由 `app` 层 `T()` 渲染 |
| `app.go:933-939` 的 Wails 原生对话框标题/正文/按钮 | 在 `app` 层按当前 locale 取字典 |
| `app.go:1223`/`:1233`/`:1268`/`:1283`/`:1294` 的错误前缀（未知工具链、安装/切换/卸载失败） | 同上 |

领域包定义**自己的**枚举、而非引入 `i18n.Key`，是为了保持领域包与语言无关：其单测断言枚举，不必按语言跑。

Go 字典与前端字典的关系是**按生产者划分**，不是按语言划分：谁产出文案，谁在两种语言下各写一份。因此不存在「同一句话两处维护」——只有 `index.json` 这类远程数据例外，见 P4。

## 八、验证方案

### 8.1 前端行为

`node --test frontend/test-app.cjs`（工作目录 `apps/desktop-launcher`）。该文件有 **37 处直接断言中文文案**，第①批已把沙箱的 `navigator` pin 为 `zh`，这些断言因此跑在键全集真源上；语言解析本身的用例（优先级、缺键回退、占位符、DOM 回填、回推 Go）在新增的 `frontend/test-i18n.cjs`（13 例）。

### 8.2 桥协议

`linglong/test-link-bridge.cjs`（9 例）覆盖：`lang` 变更触发上报、未变更不重复上报、空 `lang` 不上报、挂载完成补报一次、`targetOrigin` 取值正确。非 iframe 环境不上报由既有的「未被 iframe 内嵌时不注册任何监听」用例承担（观察器数量为 0）。

### 8.3 真实布局

`node frontend/tools/preview.mjs verify`（浅色/深色、最窄窗口）。**已实施**：`buildPreview` 剥掉脚本后内联三份国际化脚本并在页内应用当前语言（内联而非外链，因为预览页以 `file://` 打开）。不注入时静态文案为空，几何断言会误报。

同一句英文通常比中文长一截，因此几何要按语言各量一遍：默认 `zh-CN`，`DSH_PREVIEW_LOCALE=en node frontend/tools/preview.mjs verify` 量英文。两种语言下都必须「布局不变量全部成立」。

### 8.4 闸门

1. 扩展 `scripts/verify-client-ui-i18n.ts` 的 `sourceFiles()`，纳入 `apps/desktop-launcher/frontend`；为其补 `textContent`/`innerText` 赋值规则（现有该规则只对 `apps/desktop/` 生效）。
2. HTML 扫描：`index.html` 中任何含字母的文本节点，其所属元素必须带 `data-i18n` 钩子；属性文案必须走 `data-i18n-*`。解析器选型见第十节。
3. **闸门自证**：仓库要求「证明每条验收路径能拒绝无效输入」——须为 JS 硬编码文案、HTML 无钩子文本、`en.js` 缺键三类各写一条必须失败的用例。
4. `en.js` 未翻译条目数作为提示输出。

### 8.5 Go 侧

1. `go test ./...`（`make test`，`CGO_ENABLED=1`）。
2. `internal/i18n` 的**键全集一致性测试**：`en` 缺键必须失败（对齐 `apps/desktop/src/locale.ts:91` 的 `satisfies DesktopMessages` 约束——Go 无类型级约束，用测试补）。
3. `internal/toolchain/install_test.go:518` 的分类断言由「字符串包含中文」改为「枚举相等」；该测试当前断言的是 `classifyError` 的文案，改造后应断言 `ErrorKind`。
4. `internal/app` 层新增渲染函数单测：同一 key + 参数在 `zh`/`en` 下产出各自文案，且未知 key 不 panic（按 6.4 显示 key 名）。

### 8.6 打包态实测（不可省略）

`linglong/stage/` 中的 dist 是**旧产物**：`grep -c 'zh-CN'` 为 0，说明它构建于 locale 包之前，不含语言服务。因此 5.1 的结论**必须在一次真实打包态启动中实测确认**：启动后检查 iframe 的 `<html lang>` 是否随 GUI 语言变化、壳是否同步切换、Go 侧文案是否随 `SetLocale` 更新。开发态（`pnpm dsh web` 或直接跑二进制）没有注入桥，只有兜底链路，不能作为该结论的证据。
